SECTION 1

สาระสำคัญและผลการเรียนรู้ประจำบท

กรอบมาตรฐานการเรียนรู้ตามหลักสูตรแกนกลางการศึกษาขั้นพื้นฐาน และสมรรถนะสำคัญของผู้เรียน

สาระสำคัญ (Core Concept)

การจำแนกประเภทเสียงเหตุการณ์ในสิ่งแวดล้อม (Audio Classification) เช่น เสียงสัญญาณเตือนภัย เสียงกระจกแตก หรือเสียงผิดปกติของเครื่องจักรอุตสาหกรรม ต้องใช้เทคนิคการสกัดคุณลักษณะทางความถี่สเปกโทรแกรม MFE (Mel-Filterbank Energy) ร่วมกับการกรองเสียงรบกวนพื้นหลัง (Background Noise) การบูรณาการในระดับวิศวกรรมขั้นสูง (Capstone Integration) จะหลอมรวมการประมวลผลแบบพหุโมดอล (Multi-Modal AI: Computer Vision & Audio Processing) ทำงานร่วมกันบนบอร์ดพัฒนา Arduino UNO Q พร้อมทั้งบันทึกประวัติเหตุการณ์ฉุกเฉินลงในฐานข้อมูล SQLite แบบ Event-driven เพื่อสนับสนุนการวิเคราะห์ระบบการบำรุงรักษาเชิงคาดการณ์ (Predictive Maintenance) และความปลอดภัยทางอุตสาหกรรม

ผลการเรียนรู้ที่คาดหวังตามกรอบสมรรถนะ (Learning Outcomes)

K ด้านความรู้และความเข้าใจ (Knowledge)

ผู้เรียนสามารถอธิบายหลักการจำแนกเสียงเหตุการณ์ (Acoustic Events), สถาปัตยกรรมการหลอมรวมข้อมูลพหุโมดอล (Multi-Modal Sensor Fusion) และโครงสร้างระบบบำรุงรักษาเชิงคาดการณ์ได้อย่างถูกต้อง

P1 ด้านทักษะการวิเคราะห์และฝึกสอนโมเดลเสียง (Acoustic Analysis & Modeling)

ผู้เรียนสามารถบันทึกและจำแนกช่วงความถี่เสียงเหตุการณ์สิ่งแวดล้อม ออกแบบ Impulse สกัดคุณลักษณะ MFE และปรับแต่งพารามิเตอร์หลังการประมวลผล (Post-processing) เพื่อลดการแจ้งเตือนผิดพลาดได้อย่างถูกต้อง

P2 ด้านทักษะการบูรณาการระบบพหุโมดอล (Multi-Modal Capstone Integration)

ผู้เรียนสามารถติดตั้งและรันโมเดลระบบรับภาพและระบบเสียงควบคู่กันบนบอร์ด UNO Q เขียนสคริปต์บันทึกประวัติการทำงานลงฐานข้อมูล SQLite และสร้างระบบตัดวงจรฉุกเฉิน (Emergency Interlock) ได้อย่างสมบูรณ์

A ด้านคุณลักษณะและเจตคติ (Attitude & Values)

ผู้เรียนมีความตระหนักในมาตรฐานความปลอดภัยทางอุตสาหกรรมขั้นสูงสุด เคารพในกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA) ในการติดตั้งระบบดักจับเสียง และมีความรับผิดชอบต่อการพัฒนาโครงงานวิศวกรรม

ตอนที่ 1 (EP.1)

การจำแนกเสียงเครื่องจักรอุตสาหกรรม (Industrial Audio Classification)

ทำไมเสียงความผิดปกติของเครื่องจักรจึงไม่ใช้โมเดลเสียงพูด และเทคนิคการตรวจจับคลื่นเสียงความถี่สูง

เสียงการทำงานของเครื่องจักรกลในโรงงานอุตสาหกรรม (เช่น มอเตอร์ไฟฟ้า ปั๊มไฮดรอลิก เฟืองเกียร์ หรือสายพาน) มีลักษณะเป็นสัญญาณต่อเนื่องที่มีการสั่นพ้องทางกล (Mechanical Resonance) ต่างจากเสียงพูดของมนุษย์ที่มีช่องว่างของคำอย่างชัดเจน ในงานจำแนกเสียงเครื่องจักร เราจะใช้การสกัดคุณลักษณะด้วย MFE (Mel-Filterbank Energy) หรือ Spectrogram ซึ่งเก็บข้อมูลพลังงานความถี่ต่อเนื่องได้ละเอียดกว่า และฝึกสอนโมเดล 2D CNN เพื่อแยกแยะรูปแบบเสียง:

Normal_Hum (ปกติ)

เสียงมอเตอร์หมุนราบรื่น สเปกตรัมพลังงานกระจายสม่ำเสมอในย่านความถี่ต่ำถึงปานกลาง (50–1,200 Hz)

Bearing_Fault (สึกหรอ)

เสียงเสียดสีของตลับลูกปืนที่เริ่มขาดสารหล่อลื่น ปรากฏฮาร์โมนิกความถี่สูง (2,500–5,000 Hz) เป็นสัญญาณเตือนก่อนเครื่องจักรเสียหาย

Gear_Jam (วิกฤต)

เสียงกระแทกของฟันเฟืองที่ขบติดขัดหรือมีเศษโลหะติด พลังงานพุ่งสูงฉับพลัน ต้องตัดวงจรหยุดเครื่องทันที

ตอนที่ 2 (EP.2)

สถาปัตยกรรมการหลอมรวมข้อมูลพหุโมดอล (Multi-Modal Sensor Fusion)

การประสานงานระหว่างโมเดลการมองเห็น (Vision) และโมเดลเสียง (Audio) บนโปรเซสเซอร์ของ Arduino UNO Q

ในระบบอัจฉริยะขั้นสูง การพึ่งพาเซนเซอร์ชนิดเดียว (Single Modality) มักมีจุดบอด เช่น ในสภาพแสงจ้าหรือมีฝุ่นควัน กล้องอาจมองไม่เห็นตำหนิ หรือในโรงงานที่มีเสียงดัง การใช้ไมโครโฟนอย่างเดียวอาจถูกรบกวน การทำ Decision-Level Sensor Fusion เป็นการนำผลการทำนายจากทั้งสองช่องทางมารวมกัน:

ตรรกะการตัดสินใจร่วม (Dual-Confirmation Decision Matrix):
  • สภาวะที่ 1 (ชิ้นงานปกติ & เสียงปกติ): เซอร์โวมอเตอร์ปล่อยชิ้นงานผ่านสายพานตามรอบการทำงานปกติ
  • สภาวะที่ 2 (ชิ้นงานผิดรูป แต่เสียงปกติ): ก้านปัดเซอร์โวผลักชิ้นงานลงกล่องคัดแยก โดยไม่ต้องหยุดสายพาน
  • สภาวะที่ 3 (ตรวจพบเสียง Gear_Jam): สั่งตัดไฟฉุกเฉิน (E-Stop Relay) หยุดสายพานทันที แม้กล้องจะยังไม่เห็นชิ้นงานติดขัด เพื่อป้องกันเพลาหัก
ตอนที่ 3 (EP.3)

การบันทึกประวัติลงฐานข้อมูล SQLite เพื่อการบำรุงรักษาเชิงคาดการณ์

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import sys, time, datetime, sqlite3

try:
    from arduino.app_bricks.audio_classification import AudioClassification
    from arduino.app_utils import App
    IS_ARDUINO_ENV = True
except ImportError:
    IS_ARDUINO_ENV = False


class MultiModalEdgeSystem:
    """คลาสบูรณาการระบบ Edge AI เชิงวิศวกรรม (Audio + SQL Logging + E-Stop)"""
    def __init__(self, db_path=":memory:"):
        self.conn = sqlite3.connect(db_path)
        self.init_database()

    def init_database(self):
        with self.conn:
            self.conn.execute("""
                CREATE TABLE IF NOT EXISTS machine_audit_logs (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    timestamp TEXT NOT NULL,
                    sensor_type TEXT NOT NULL,
                    event_label TEXT NOT NULL,
                    confidence REAL NOT NULL,
                    severity TEXT NOT NULL,
                    action_taken TEXT NOT NULL
                )
            """)

    def handle_acoustic_event(self, label: str, confidence: float):
        timestamp = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        if label.lower() in ["background", "ambient"]:
            return

        severity = "NORMAL"
        action = "บันทึกประวัติการเดินเครื่องปกติ"

        if label in ["Bearing_Fault"]:
            severity = "WARNING"
            action = "ส่งสัญญาณแจ้งเตือนช่างซ่อมบำรุง (Yellow LED ON)"
        elif label in ["Gear_Jam"]:
            severity = "CRITICAL"
            action = "ตัดวงจรฉุกเฉิน (Relay E-Stop Pin 7 = HIGH) และเปิด Buzzer"

        with self.conn:
            self.conn.execute("""
                INSERT INTO machine_audit_logs (timestamp, sensor_type, event_label, confidence, severity, action_taken)
                VALUES (?, ?, ?, ?, ?, ?)
            """, (timestamp, "ACOUSTIC_MIC", label, confidence, severity, action))

        print(f"[{severity}] [{timestamp}] พบเสียง '{label}' ({confidence*100:.1f}%) -> {action}")

คำถามทบทวนองค์ความรู้ท้ายบทเรียน (Review Questions)

ทดสอบความเข้าใจเชิงลึกเกี่ยวกับการบูรณาการระบบ Edge AI และการบำรุงรักษาเชิงคาดการณ์

1. การประมวลผลแบบพหุโมดอล (Multi-Modal AI) ช่วยแก้ปัญหาจุดบอดของการใช้เซนเซอร์ภาพหรือไมโครโฟนเพียงอย่างเดียวในโรงงานอุตสาหกรรมอย่างไร?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: ในสภาพแวดล้อมโรงงานจริง เซนเซอร์ภาพอาจถูกบดบังด้วยควัน ฝุ่นละออง หรือการเปลี่ยนแปลงของแสงไฟ ทำให้ตรวจจับตำหนิผิดพลาด ในขณะที่ไมโครโฟนสามารถดักจับการสั่นสะเทือนและเสียงผิดปกติภายในตลับลูกปืนหรือเฟืองเกียร์ที่ตาเปล่ามองไม่เห็นได้ ในทางกลับกัน ภาพจะช่วยยืนยันตำแหน่งและรูปร่างของชิ้นงานได้แม่นยำกว่าเสียง การหลอมรวมข้อมูลทั้งสองช่วยสร้างระบบยืนยันคู่ (Dual Confirmation) เพิ่มความแม่นยำ ลด False Alarm และช่วยให้การตัดสินใจสั่งการฉุกเฉินถูกต้องแม่นยำสูงสุด
2. เพราะเหตุใดในการบำรุงรักษาเชิงคาดการณ์ (Predictive Maintenance) จึงจำเป็นต้องมีระบบบันทึกฐานข้อมูลในอุปกรณ์ (Database-SQL) แทนการแสดงผลสดบนหน้าจอเพียงอย่างเดียว?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: การแสดงผลสดจะบอกเฉพาะสภาวะปัจจุบันในเสี้ยววินาทีนั้น แต่การพยากรณ์ความเสื่อมสภาพของเครื่องจักรจำเป็นต้องวิเคราะห์แนวโน้มเชิงสถิติ (Trend Analysis) เช่น เสียงสัญญาณ Bearing_Fault เริ่มปรากฏความถี่บ่อยขึ้นจาก 1 ครั้งต่อวัน เป็น 10 ครั้งต่อชั่วโมง การบันทึกประวัติลงฐานข้อมูล SQLite ในอุปกรณ์ช่วยสร้างหลักฐานทางวิศวกรรม (Audit Trail) ทำให้สามารถประมวลผลสร้างกราฟแนวโน้ม และวางแผนกำหนดการเปลี่ยนอะไหล่ล่วงหน้าได้ก่อนที่เครื่องจักรจะพังฉับพลัน
3. ในการออกแบบระบบตัดวงจรฉุกเฉิน (Emergency Interlock) เพื่อความปลอดภัยอุตสาหกรรม มีหลักการออกแบบฮาร์ดแวร์และซอฟต์แวร์อย่างไรให้เป็นระบบ Fail-Safe?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: ในเชิงฮาร์ดแวร์ ต้องออกแบบวงจรตัดต่อแบบ Normally Closed (NC) ซึ่งหากเกิดเหตุสายสัญญาณขาดหรือไฟเลี้ยงระบบตก วงจรจะตัดการจ่ายไฟแก่มอเตอร์ทันทีเพื่อความปลอดภัย ในเชิงซอฟต์แวร์ ต้องกำหนดเกณฑ์ความเชื่อมั่นที่เข้มงวดและมี Watchdog Timer ตรวจสอบสถานะการประมวลผล หากโมเดลตรวจพบความผิดปกติระดับ CRITICAL (เช่น Gear_Jam) ระบบต้องส่งสัญญาณตัดวงจรรีเลย์ทันทีในระดับ Local Edge โดยไม่ต้องรอคำสั่งจากคลาวด์ เพื่อให้หยุดเครื่องจักรได้ภายในเสี้ยววินาที
