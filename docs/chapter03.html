SECTION 1

สาระสำคัญและผลการเรียนรู้ประจำบท

กรอบมาตรฐานการเรียนรู้ตามหลักสูตรแกนกลางการศึกษาขั้นพื้นฐาน และสมรรถนะสำคัญของผู้เรียน

สาระสำคัญ (Core Concept)

ในระบบปัญญาประดิษฐ์บนอุปกรณ์ปลายทางระดับวิศวกรรม การประมวลผลโมเดล AI เพียงอย่างเดียวไม่เพียงพอต่อการนำไปใช้งานจริง จำเป็นต้องมีกลไกจัดเก็บประวัติเหตุการณ์การทำนาย (Inference Event Logging) เพื่อให้ระบบสามารถตรวจสอบย้อนหลัง (Audit Trail & Traceability) ได้อย่างแม่นยำ Database-SQL Brick บนบอร์ดพัฒนา Arduino UNO Q ทำหน้าที่ผสานพลังของระบบจัดการฐานข้อมูลเชิงสัมพันธ์ SQLite บนหน่วยประมวลผล 64 บิต Qualcomm QRB2210 ทำให้อุปกรณ์สามารถบันทึกผลการคัดแยกชิ้นงาน พิกัดของวัตถุ หรือคำสั่งเสียงลงในไฟล์ฐานข้อมูลภายในเครื่องได้อย่างรวดเร็วและปลอดภัยภายใต้สถาปัตยกรรม Offline-First โดยไม่ต้องพึ่งพาระบบคลาวด์หรือการเชื่อมต่ออินเทอร์เน็ตภายนอกตลอดเวลา

ผลการเรียนรู้ที่คาดหวังตามกรอบสมรรถนะ (Learning Outcomes)

K ด้านความรู้และความเข้าใจ (Knowledge)

ผู้เรียนสามารถอธิบายหลักการทำงานของ Database-SQL Brick, สถาปัตยกรรมฐานข้อมูลแบบ Serverless (SQLite), และความจำเป็นของการบันทึกประวัติการตรวจจับ AI บนอุปกรณ์ปลายทางได้อย่างถูกต้องตามหลักวิชาการ

P1 ด้านทักษะการออกแบบและจัดการฐานข้อมูล (Database Schema)

ผู้เรียนสามารถออกแบบโครงสร้างตารางข้อมูลเชิงสัมพันธ์ (SQL Tables) และเขียนคำสั่ง CREATE TABLE เพื่อจัดเก็บพารามิเตอร์ของโมเดล AI (เช่น Anomaly Scores, Bounding Boxes, และ Voice Keywords) ได้อย่างถูกต้อง

P2 ด้านทักษะการเขียนโปรแกรมและการสืบค้นข้อมูล (SQL Analytics)

ผู้เรียนสามารถเขียนชุดคำสั่งภาษาไพทอนเพื่อแทรกบันทึกข้อมูล (INSERT) และสืบค้นรายงานสรุปผลเชิงสถิติ (SELECT ... GROUP BY) เพื่อแสดงอัตราส่วนของดี/ของเสียได้อย่างมีประสิทธิภาพ

A ด้านคุณลักษณะและเจตคติ (Attitude & Values)

ผู้เรียนตระหนักถึงความสำคัญของความถูกต้องและครบถ้วนของข้อมูล (Data Integrity) มีความรอบคอบในการจัดสรรพื้นที่จัดเก็บบนอุปกรณ์ และมีความรับผิดชอบต่อการจัดการข้อมูลตามหลักจริยธรรมข้อมูล

ตอนที่ 1: สถาปัตยกรรมฐานข้อมูลบนอุปกรณ์ปลายทาง

สถาปัตยกรรมระบบฐานข้อมูลบนอุปกรณ์ปลายทาง (Edge Database Architecture)

ในระบบอัตโนมัติภาคอุตสาหกรรม (Industry 4.0) การส่งข้อมูลผลการวิเคราะห์ของ AI กลับไปบันทึกบนคลาวด์ทุกวินาทีไม่สามารถทำได้เสมอไป เนื่องจากข้อจำกัดด้านความหน่วงของเครือข่าย (Network Latency), ปัญหาความไม่เสถียรของสัญญาณอินเทอร์เน็ต และต้นทุนค่าบริการคลาวด์ที่สูง ดังนั้น การมี ระบบฐานข้อมูลท้องถิ่นในตัวอุปกรณ์ (Embedded On-Device Database) จึงเป็นหัวใจสำคัญของการออกแบบระบบ Edge AI

SQLite เป็นระบบจัดการฐานข้อมูลเชิงสัมพันธ์แบบฝังตัว (Embedded Relational Database Management System) ที่ได้รับความนิยมสูงสุดในระดับสากล เนื่องจากมีคุณลักษณะเฉพาะที่โดดเด่น:

  • ไร้เซิร์ฟเวอร์ (Serverless Architecture): ไม่จำเป็นต้องเปิดรัน Background Service หรือดาต้าเบสเซิร์ฟเวอร์แยกต่างหาก โดยไบนารีและเอนจินของฐานข้อมูลจะรวมเป็นส่วนหนึ่งของกระบวนการทำงานในโปรแกรมภาษาไพทอนโดยตรง
  • ไฟล์เดี่ยวจัดเก็บสมบูรณ์ (Single File Storage): ฐานข้อมูล ตาราง ดัชนี และข้อมูลทั้งหมดจะถูกบันทึกเป็นไฟล์ไบนารีเดี่ยว เช่น edgeai_records.db ทำให้การสำรองข้อมูล (Backup) หรือการโอนย้ายไฟล์ทำได้อย่างสะดวกง่ายดาย
  • มาตรฐานความถูกต้องปลอดภัย (ACID Compliant): รองรับคุณสมบัติ Atomicity, Consistency, Isolation, และ Durability ทำให้มั่นใจได้ว่าข้อมูลจะไม่เสียหาย แม้จะเกิดเหตุการณ์ไฟดับกะทันหันในโรงงาน

ตอนที่ 2: การออกแบบฐานข้อมูลเชิงสัมพันธ์

การออกแบบโครงสร้างตารางข้อมูลเพื่อรองรับโมเดล AI (Database Schema Design)

เพื่อให้ระบบ Edge AI สามารถจัดเก็บผลลัพธ์ของโมเดลปัญญาประดิษฐ์ประเภทต่าง ๆ ในหลักสูตรได้อย่างครอบคลุม โครงสร้างฐานข้อมูลจึงได้รับการออกแบบแยกเป็น 3 ตารางหลักตามประเภทของภารกิจ AI:

1. ตาราง anomaly_logs (Visual Anomaly Detection) งานตรวจสอบคุณภาพชิ้นงาน

ใช้บันทึกผลการตรวจสอบพื้นผิวชิ้นงานผิดปกติจากโมเดล Visual Anomaly Detection (บทที่ 5 และ 7)

Database-SQL Brick 
import os
import sqlite3

# ดึงตำแหน่งไฟล์ฐานข้อมูลจากตัวแปรสภาพแวดล้อมที่ระบุใน app.yaml
DB_PATH = os.environ.get("DB_FILE_PATH", "edgeai_records.db")

def init_database():
    """สร้างไดเรกทอรีและตารางฐานข้อมูลหากยังไม่มีในระบบ"""
    os.makedirs(os.path.dirname(os.path.abspath(DB_PATH)), exist_ok=True)
    conn = sqlite3.connect(DB_PATH)
    cursor = conn.cursor()
    
    # 1. ตารางบันทึกประวัติการตรวจจับความผิดปกติ (Visual Anomaly)
    cursor.execute('''
        CREATE TABLE IF NOT EXISTS anomaly_logs (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
            model_name TEXT NOT NULL,
            anomaly_mean_score REAL,
            anomaly_max_score REAL NOT NULL,
            status TEXT NOT NULL,
            alert_triggered INTEGER DEFAULT 0
        )
    ''')
    
    conn.commit()
    conn.close()
    print(f"[Database-SQL Brick] เริ่มต้นโครงสร้างฐานข้อมูลสำเร็จ: {DB_PATH}")

def log_anomaly_event(model_name, mean_score, max_score, threshold=15.0):
    """ฟังก์ชันบันทึกผลการทำนายของโมเดล AI ลงฐานข้อมูล"""
    status = "DEFECT" if max_score >= threshold else "NORMAL"
    alert = 1 if status == "DEFECT" else 0
    
    conn = sqlite3.connect(DB_PATH)
    cursor = conn.cursor()
    # ใช้พารามิเตอร์ (?) เพื่อป้องกัน SQL Injection และความผิดพลาดของชนิดข้อมูล
    cursor.execute('''
        INSERT INTO anomaly_logs (model_name, anomaly_mean_score, anomaly_max_score, status, alert_triggered)
        VALUES (?, ?, ?, ?, ?)
    ''', (model_name, mean_score, max_score, status, alert))
    conn.commit()
    conn.close()
    print(f"[SQL Insert] บันทึกผล: {status} (Max Score: {max_score:.2f}, Alert: {alert})")

ในการเขียนคำสั่ง SQL ผ่านภาษาไพทอน ห้ามใช้การต่อสตริงโดยตรง เช่น f"INSERT INTO ... VALUES ('{status}')" เพราะอาจเกิดข้อผิดพลาดจากอักขระพิเศษ (เช่น เครื่องหมายคำพูดเดี่ยว) และเสี่ยงต่อช่องโหว่ความปลอดภัย ต้องใช้เครื่องหมายคำถามปรนัย ? เป็น Placeholder เสมอ

SELECT 
    status, 
    COUNT(*) AS total_count,
    ROUND(AVG(anomaly_max_score), 2) AS avg_max_score
FROM anomaly_logs
WHERE DATE(timestamp) = DATE('now')
GROUP BY status;

คำถามทบทวนองค์ความรู้ท้ายบทเรียน (Academic Review Questions)

แบบฝึกหัดสำหรับประเมินตนเองและทบทวนเนื้อหาสำคัญเพื่อเตรียมความพร้อมสู่การปฏิบัติการขั้นสูง

1. เหตุใดระบบจัดการฐานข้อมูล SQLite จึงเหมาะสมสำหรับการนำมาใช้งานบนอุปกรณ์สมองกลฝังตัว เช่น บอร์ด Arduino UNO Q มากกว่าระบบ MySQL หรือ PostgreSQL?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: เนื่องจาก SQLite มีสถาปัตยกรรมแบบ ไร้เซิร์ฟเวอร์ (Serverless) และใช้พื้นที่หน่วยความจำน้อยมาก (Lightweight) โดยเอนจินของฐานข้อมูลจะรวมเป็นส่วนหนึ่งของไลบรารีในโปรแกรมภาษาไพทอน ข้อมูลทั้งหมดจัดเก็บอยู่ในไฟล์เดี่ยวบนระบบไฟล์ของลีนุกซ์ ไม่ต้องมีการเปิดพอร์ตหรือรัน Background Daemon Services ตลอดเวลา จึงช่วยประหยัดทั้งแรม (RAM) และพลังงานของบอร์ดพัฒนา แตกต่างจาก MySQL หรือ PostgreSQL ที่ต้องมีเซิร์ฟเวอร์แยกต่างหากและกินทรัพยากรระบบสูง
2. ในงานตรวจสอบคุณภาพผลิตภัณฑ์ด้วยปัญญาประดิษฐ์ (Edge AI Quality Control) การบันทึกค่า Anomaly Score และสถานะการตรวจจับลงฐานข้อมูลในเครื่องมีประโยชน์เชิงวิศวกรรมอย่างไร?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: มีประโยชน์หลัก 3 ประการ: 1) การตรวจสอบย้อนหลัง (Audit Trail & Traceability): สามารถตรวจสอบประวัติได้ว่าชิ้นงานชิ้นใดมีรอยตำหนิ ตรวจพบเมื่อเวลาใด และด้วยคะแนนความผิดปกติเท่าใด 2) การวิเคราะห์แนวโน้มและการบำรุงรักษาเชิงคาดการณ์ (Predictive Maintenance): หากค่าเฉลี่ยของ Anomaly Score ค่อยๆ สูงขึ้นตามช่วงเวลา แม้จะยังไม่เกินเกณฑ์ Threshold ก็สามารถแจ้งเตือนให้วิศวกรเข้าตรวจสอบใบมีดหรือความเสื่อมสภาพของเครื่องจักรได้ล่วงหน้า 3) การทำงานแบบออฟไลน์ (Offline Resilience): ระบบสามารถบันทึกข้อมูลได้อย่างต่อเนื่องแม้สัญญาณอินเทอร์เน็ตของโรงงานจะหยุดชะงัก
3. ในคำสั่ง SQL การใช้ GROUP BY status ร่วมกับฟังก์ชัน COUNT(*) มีหลักการทำงานอย่างไร และนำมาประยุกต์ใช้ในงานอุตสาหกรรมอย่างไร?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: คำสั่ง GROUP BY status จะจัดกลุ่มแถวข้อมูลที่มีค่าในคอลัมน์ status เหมือนกันเข้าด้วยกัน (เช่น กลุ่ม 'NORMAL' และกลุ่ม 'DEFECT') จากนั้นฟังก์ชัน COUNT(*) จะนับจำนวนรายการทั้งหมดในแต่ละกลุ่ม ในงานอุตสาหกรรม คำสั่งนี้ช่วยให้เราคำนวณ อัตราส่วนของเสีย (Defect Rate Percentage) และสรุปรายงานผลการผลิตประจำวันได้ทันทีด้วยการรันคำสั่งเพียงบรรทัดเดียว
