สภาพแวดล้อมที่รองรับ

บอร์ดพัฒนา Arduino UNO Q, มอดูลกล้องเว็บแคม USB (UVC), เซอร์โวมอเตอร์ (SG90/MG996R) และมอดูลรีเลย์ควบคุมระบบคัดแยก

รายการครุภัณฑ์และอุปกรณ์ปฏิบัติการ
  • บอร์ดพัฒนา Arduino UNO Q (ชิปหน่วยประมวลผล Qualcomm Dragonwing QRB2210)
  • กล้อง USB UVC Webcam สำหรับตรวจจับพิกัดวัตถุสด
  • ชุดเซอร์โวมอเตอร์ (Servo Motor / Actuator) หรือโมดูลรีเลย์สำหรับคัดแยกชิ้นงาน
  • สายเชื่อมต่อ USB Type-C, สายสัญญาณ Jumper Wires และแหล่งจ่ายไฟภายนอก 5V

SECTION 1

สาระสำคัญและผลการเรียนรู้ประจำบท

กรอบมาตรฐานการเรียนรู้ตามหลักสูตรแกนกลางการศึกษาขั้นพื้นฐาน และสมรรถนะสำคัญของผู้เรียน

สาระสำคัญ (Core Concept)

การแปลงผลลัพธ์การมองเห็นของปัญญาประดิษฐ์ไปสู่การทำงานเชิงกลในโลกจริง คือหัวใจสำคัญของระบบอัตโนมัติ โดยการนำโมเดล FOMO (.eim) มาประมวลผลภาพสดจากกล้องเว็บแคม USB แบบเวลาจริง จากนั้นเขียนโปรแกรมภาษาไพทอนเพื่อสกัดพิกัดจุดกึ่งกลางของวัตถุ (Centroid Coordinates X, Y) นำมาเปรียบเทียบกับพื้นที่สนใจเสมือน (Virtual ROI) และแปลงเป็นสัญญาณสั่งการอุปกรณ์ขับเคลื่อน (Actuators) เช่น เซอร์โวมอเตอร์หรือกระบอกสูบลม ในการผลักหรือหยิบชิ้นงานคัดแยกตามพิกัดที่กำหนด พร้อมทั้งส่งสตรีมภาพผลลัพธ์ขึ้นแสดงบน Web UI มอนิเตอร์ผ่านเครือข่าย

ผลการเรียนรู้ที่คาดหวังตามกรอบสมรรถนะ (Learning Outcomes)

K ด้านความรู้และความเข้าใจ (Knowledge)

ผู้เรียนสามารถอธิบายกระบวนการแปลงผลลัพธ์พิกัดตรวจจับของโมเดล FOMO สู่สัญญาณควบคุมอุปกรณ์ขับเคลื่อน (Actuator) เชิงกล และเข้าใจบทบาทของตัวแปรสภาพแวดล้อมในไฟล์ app.yaml ได้อย่างถูกต้อง

P1 ด้านทักษะการกำหนดค่าและการสตรีม (Configuration & Web Streaming)

ผู้เรียนสามารถกำหนดค่าตัวแปร EI_OBJ_DETECTION_MODEL ในไฟล์ app.yaml เชื่อมต่อกล้องเว็บแคมเข้ากับบอร์ด Arduino UNO Q และเปิดมอนิเตอร์ภาพผลลัพธ์ผ่านพอร์ต 7000 ได้อย่างถูกต้อง

P2 ด้านทักษะการควบคุมอุปกรณ์ขับเคลื่อน (Actuator Control & Closed-Loop)

ผู้เรียนสามารถพัฒนาโปรแกรมภาษาไพทอนเพื่อสกัดพิกัดจุดกึ่งกลาง (Centroid) และส่งสัญญาณควบคุมเซอร์โวมอเตอร์เพื่อผลักชิ้นงานคัดแยกตามตำแหน่งในพื้นที่เสมือน (Virtual ROI) ได้อย่างแม่นยำ

A ด้านคุณลักษณะและเจตคติ (Attitude & Values)

ผู้เรียนมีความตระหนักถึงความปลอดภัยในการควบคุมระบบกลไกอัตโนมัติ การแยกแหล่งจ่ายไฟของอุปกรณ์ขับเคลื่อนเพื่อป้องกันสัญญาณรบกวน และมีความรับผิดชอบต่อการปฏิบัติงานในห้องปฏิบัติการ

ส่วนที่ 2: สถาปัตยกรรมระบบ

สถาปัตยกรรมการตรวจจับวัตถุและสั่งการอุปกรณ์ขับเคลื่อน (Actuator Integration Architecture)

การผสานงานระหว่างโมเดล FOMO บนระบบประมวลผลความเร็วสูง เข้ากับอุปกรณ์ขับเคลื่อนเชิงกลผ่าน Modular Brick

รูปที่ 9.1: แผนภาพสถาปัตยกรรมการเชื่อมต่อระหว่างบอร์ดพัฒนา Arduino UNO Q, มอดูลกล้อง USB, โมเดล FOMO .eim และอุปกรณ์ขับเคลื่อน (Actuator)

ขั้นตอนการไหลของข้อมูลและสัญญาณควบคุม (Data & Signal Flow):

  1. การรับสัญญาณภาพ (Image Ingestion): มอดูลกล้องเว็บแคม USB ส่งเฟรมภาพสดเข้าสู่ Linux Core ผ่าน Video Driver
  2. การประมวลผลด้วยโมเดล FOMO (.eim): โมเดลแปลงภาพเป็นสเกลสีเทา (Grayscale) ทำการพยากรณ์โครงข่ายประสาทเพื่อหาตำแหน่ง Heatmap Peak
  3. การสกัดพิกัดจุดกึ่งกลาง (Centroid Extraction): สคริปต์ไพทอนแปลงตำแหน่ง Grid Cell เป็นพิกัดพิกเซลจริง $(cx, cy)$ และขนาดกรอบขอบเขต $(w, h)$
  4. การตัดสินใจเชิงตรรกะ (Decision Engine): เปรียบเทียบชนิดของวัตถุและพิกัดตำแหน่ง เพื่อกำหนดองศาการหมุนของเซอร์โวมอเตอร์
  5. การส่งคำสั่งสู่อุปกรณ์ขับเคลื่อน (Actuator Control): ส่งสัญญาณคำสั่งดิจิทัลหรือ PWM ผ่านพิน GPIO ไปยังเซอร์โวมอเตอร์เพื่อผลักชิ้นงานลงช่องคัดแยกที่ถูกต้อง
ตอนที่ 1 (EP.1)

การติดตั้งโมเดล FOMO (.eim) และการกำหนดค่าในไฟล์ app.yaml

ทำความเข้าใจไฟล์ไบนารี .eim และการตั้งค่าตัวแปรสภาพแวดล้อมเพื่อเตรียมความพร้อมให้กับ Video Object Detection Brick

หลังจากเสร็จสิ้นการฝึกสอนโมเดล FOMO บน Edge Impulse Studio ในบทที่ 8 ขั้นตอนถัดมาคือการนำโมเดลไปใช้งานบนอุปกรณ์จริง โดยคอมไพล์ออกมาในรูปแบบไฟล์ไบนารีชนิด .eim (Edge Impulse Model) ซึ่งเป็นรูปแบบไบนารีแบบเนทีฟ (Native Binary Executable) ที่ผ่านการปรับแต่งประสิทธิภาพ (Optimization) ด้วยชุดคำสั่งเฉพาะของซีพียู ทำให้ประมวลผลได้รวดเร็วสูงสุดโดยใช้หน่วยความจำต่ำ

โครงสร้างไฟล์คอนฟิกูเรชัน app.yaml สำหรับระบบตรวจจับวัตถุและคัดแยก:

app.yaml (Configuration) YAML Config 
name: "FOMO Object Detection & Actuator Sorter"
description: "ระบบตรวจจับตำแหน่งวัตถุด้วยโมเดล FOMO และควบคุมอุปกรณ์ขับเคลื่อนคัดแยกชิ้นงาน"
ports:
  - 7000:7000

bricks:
  - arduino:video_object_detection:
      variables:
        EI_OBJ_DETECTION_MODEL: "/home/arduino/.arduino-bricks/ei-models/fomo_sorter.eim"
        CONFIDENCE_THRESHOLD: "0.65"
  - arduino:web_ui: {}
  - arduino:actuator_control:
      variables:
        SERVO_PIN: "9"
        RELAY_PIN: "7"
ข้อสำคัญเกี่ยวกับตัวแปร EI_OBJ_DETECTION_MODEL

พาธของไฟล์โมเดลที่ระบุใน EI_OBJ_DETECTION_MODEL ต้องเป็นพาธสัมบูรณ์ (Absolute Path) บนระบบปฏิบัติการของบอร์ดพัฒนา และไฟล์โมเดลจะต้องได้รับสิทธิ์การรัน (Execution Permission) โดยใช้คำสั่ง chmod +x <filename>.eim ก่อนเริ่มระบบ

ตอนที่ 2 (EP.2)

การสกัดพิกัดจุดกึ่งกลาง (Centroid Coordinates) และพื้นที่เสมือน (Virtual ROI)

สูตรทางคณิตศาสตร์ในการคำนวณตำแหน่งจุดศูนย์กลางของวัตถุ และการกำหนดขอบเขตคัดแยกบนภาพ

สถาปัตยกรรม FOMO ให้ผลลัพธ์เป็นตารางกริดที่ระบุตำแหน่งกึ่งกลางของวัตถุ ซึ่งต่างจากสถาปัตยกรรม Bounding Box ขนาดใหญ่ทั่วไป โดยค่าพิกัดที่ได้รับจากมอดูลจะประกอบด้วยตำแหน่งมุมซ้ายบน $(x, y)$ ขนาดความกว้าง $(w)$ และความสูง $(h)$ ในการนำไปควบคุมอุปกรณ์ขับเคลื่อนเชิงกล เราจำเป็นต้องคำนวณหา พิกัดจุดกึ่งกลาง (Centroid) เพื่อเป็นตัวแทนตำแหน่งที่แท้จริงของชิ้นงาน

สูตรการคำนวณพิกัดจุดกึ่งกลาง (Centroid Formula):
cx = x + \lfloor \frac{w}{2} \rfloor \quad , \quad cy = y + \lfloor \frac{h}{2} \rfloor

เมื่อ x, y คือพิกัดเริ่มต้นมุมซ้ายบน และ w, h คือความกว้างและความสูงของกรอบตรวจจับ หน่วยเป็นพิกเซล (Pixels)

การกำหนดพื้นที่คัดแยกเสมือนบนสายพานลำเลียง (Virtual Sorting Zones):

โซนซ้าย (Left Zone: cx < 100)

สำหรับชิ้นงานกลุ่ม Bolt (สลักเกลียว) สั่งการเซอร์โวมอเตอร์หมุนก้านปัดไปยังมุม 45° เพื่อปัดชิ้นงานลงกล่องคัดแยก A

โซนกลาง (Center: 100 ≤ cx ≤ 220)

สำหรับชิ้นงานกลุ่ม Bearing (ตลับลูกปืน) เซอร์โวมอเตอร์คงตำแหน่ง 90° (กึ่งกลาง) เพื่อปล่อยให้ชิ้นงานไหลผ่านสายพานตรง C

โซนขวา (Right Zone: cx > 220)

สำหรับชิ้นงานกลุ่ม Nut (แป้นเกลียว) สั่งการเซอร์โวมอเตอร์หมุนก้านปัดไปยังมุม 135° เพื่อปัดชิ้นงานลงกล่องคัดแยก B

ตอนที่ 3 (EP.3)

การควบคุมอุปกรณ์ขับเคลื่อน (Actuator) และการเชื่อมต่อฮาร์ดแวร์

การสร้างสัญญาณควบคุมมุมองศาเซอร์โวมอเตอร์ และการออกแบบวงจรแยกแหล่งจ่ายกำลังเพื่อความปลอดภัย

อุปกรณ์ขับเคลื่อน (Actuator) คือส่วนประกอบทางกายภาพที่เปลี่ยนสัญญาณไฟฟ้าจากการประมวลผลของปัญญาประดิษฐ์ให้กลายเป็นการเคลื่อนไหวเชิงกล เช่น เซอร์โวมอเตอร์ (Servo Motor) โซลินอยด์วาล์ว (Solenoid Valve) หรือกระบอกสูบลม ในบทเรียนนี้เราใช้เซอร์โวมอเตอร์ที่มีแกนหมุนก้านปัดในการคัดแยกชิ้นงานบนสายพาน

สัญญาณควบคุมแบบ PWM (Pulse Width Modulation)
  • ความถี่สัญญาณมาตรฐาน: 50 Hz (คาบเวลา 20 ms)
  • ความกว้างพัลส์ 1.0 ms: ควบคุมแกนหมุนไปยังมุม 0°
  • ความกว้างพัลส์ 1.5 ms: ควบคุมแกนหมุนไปยังมุม 90° (ตรงกลาง)
  • ความกว้างพัลส์ 2.0 ms: ควบคุมแกนหมุนไปยังมุม 180°
ข้อควรระวังด้านแหล่งจ่ายไฟ (Power Supply)
  • ห้าม ดึงไฟเลี้ยง 5V ของเซอร์โวมอเตอร์โดยตรงจากขาของบอร์ด Arduino
  • ให้ใช้ แหล่งจ่ายไฟแยกภายนอก (External 5V/2A) สำหรับอุปกรณ์ขับเคลื่อน
  • ต้อง เชื่อมต่อขั้วกราวด์ (Common Ground) ระหว่างบอร์ดและแหล่งจ่ายไฟเสมอ
รูปที่ 9.2: ภาพการทำงานแบบเวลาจริง แสดงการคำนวณพิกัดจุดกึ่งกลาง (Centroid) และสถานะการสั่งการอุปกรณ์ขับเคลื่อน
ตอนที่ 4 (EP.4)

การจัดการวงจรปิด (Closed-Loop) และการจัดการข้อผิดพลาดในการตรวจจับ

ตรรกะการตรวจสอบสถานะของอุปกรณ์ขับเคลื่อน การกรองความผิดพลาด (False Detection) และการบันทึกประวัติการทำงาน

ในสภาพแวดล้อมการผลิตจริง การสั่งการอุปกรณ์ขับเคลื่อนโดยปราศจากการตรวจสอบสถานะการทำงาน (Open-Loop Control) อาจก่อให้เกิดปัญหาชิ้นงานติดขัด (Jam) หรือก้านปัดชนกับชิ้นงานถัดไป ระบบที่สมบูรณ์จึงต้องมีโครงสร้างการควบคุมแบบวงจรปิด (Closed-Loop Control) ซึ่งประกอบด้วย 3 องค์ประกอบสำคัญ:

1. การล็อกสถานะ (Actuator Busy Lock)

เมื่อสั่งการเซอร์โวมอเตอร์ ระบบจะตั้งค่าสถานะ is_busy = True เพื่อป้องกันไม่ให้คำสั่งใหม่เข้าแทรกแซงในระหว่างที่กลไกกำลังหมุนคัดแยก

2. การกรองความเชื่อมั่น (Confidence Thresholding)

ตัดสัญญาณรบกวนที่มีค่าความเชื่อมั่นต่ำกว่าเกณฑ์ (เช่น < 0.65) เพื่อป้องกันการหมุนก้านปัดโดยไม่จำเป็นจากวัตถุเงาหรือการสั่นไหวของแสง

3. การแจ้งเตือนฉุกเฉิน (Relay Alarm / Defect Ejection)

หากพบชิ้นส่วนแปลกปลอม (Unknown Object) ที่มีขนาดผิดปกติ ระบบจะสั่งเปิดรีเลย์ไฟสัญญาณเตือนและผลักชิ้นงานลงช่องคัดแยกพิเศษทันที

ส่วนที่ 4: ตัวอย่างโค้ดและการทดสอบภาคปฏิบัติ

class ActuatorController:
    """คลาสควบคุมอุปกรณ์ขับเคลื่อน (Actuator / Servo Motor / Relay) สำหรับคัดแยกชิ้นงาน"""
    def __init__(self, servo_pin=9, relay_pin=7):
        self.servo_pin = servo_pin
        self.relay_pin = relay_pin
        self.current_angle = 90  # องศาตั้งต้น (ตรงกลาง)

    def move_servo(self, target_angle, action_name=""):
        self.current_angle = target_angle
        print(f"    [Actuator] สั่งการพิน {self.servo_pin}: หมุนก้านปัดไปยังมุม {target_angle}° ({action_name})")
        time.sleep(0.05)

    def trigger_relay(self, state=True):
        status = "เปิดทำงาน (ON)" if state else "ปิดทำงาน (OFF)"
        print(f"    [Relay] สั่งการพิน {self.relay_pin}: {status}")


class FomoLiveInspector:
    """คลาสประมวลผลผลลัพธ์จากโมเดล FOMO และสั่งการอุปกรณ์ขับเคลื่อน"""
    def __init__(self, confidence_threshold=0.65):
        self.threshold = confidence_threshold
        self.actuator = ActuatorController(servo_pin=9, relay_pin=7)
        self.total_sorted = {"Bolt": 0, "Nut": 0, "Bearing": 0, "Unknown": 0}

    def process_detections(self, detections):
        if not detections:
            return

        valid = [item for item in detections if getattr(item, 'confidence', 0.0) >= self.threshold]
        for item in valid:
            label = getattr(item, 'label', 'Unknown')
            conf = getattr(item, 'confidence', 0.0)
            x = getattr(item, 'x', 0)
            y = getattr(item, 'y', 0)
            w = getattr(item, 'width', 0)
            h = getattr(item, 'height', 0)
            cx, cy = x + (w // 2), y + (h // 2)

            print(f"  - พบวัตถุ: [{label}] ความเชื่อมั่น: {conf*100:.1f}% | พิกัดกึ่งกลาง: ({cx}, {cy})")

            if label.lower() == "bolt":
                self.actuator.move_servo(45, "ปัดสลักเกลียว -> ลงกล่องซ้าย A")
                self.total_sorted["Bolt"] += 1
            elif label.lower() == "nut":
                self.actuator.move_servo(135, "ปัดแป้นเกลียว -> ลงกล่องขวา B")
                self.total_sorted["Nut"] += 1
            elif label.lower() == "bearing":
                self.actuator.move_servo(90, "ตลับลูกปืน -> ปล่อยผ่านสายพานตรง C")
                self.total_sorted["Bearing"] += 1
            else:
                self.actuator.move_servo(0, "วัตถุแปลกปลอม -> ผลักลงกล่องตรวจสอบ D")
                self.actuator.trigger_relay(True)
                self.total_sorted["Unknown"] += 1

คำถามทบทวนองค์ความรู้ท้ายบทเรียน (Review Questions)

ทดสอบความเข้าใจเชิงลึกเกี่ยวกับหลักการทำงานของระบบคัดแยกวัตถุด้วย Edge AI

1. เหตุใดโมเดลสถาปัตยกรรม FOMO จึงเหมาะสำหรับการนำมาเชื่อมต่อกับอุปกรณ์ขับเคลื่อน (Actuator) ในระบบคัดแยกแบบเวลาจริงมากกว่าโมเดลตรวจจับวัตถุประเภท Bounding Box ขนาดใหญ่ทั่วไป?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: เนื่องจากโมเดล FOMO ถูกออกแบบมาเพื่อทำนายจุดศูนย์กลางของวัตถุโดยตรง (Centroid Heatmap) โดยตัดขั้นตอนการคำนวณสเกลของ Anchor Boxes ที่ซับซ้อนออกไป ส่งผลให้โมเดลมีขนาดเล็กมาก ประมวลผลได้ด้วยอัตราเร็วเฟรมสูง (25–35 FPS ขึ้นไป) และมีความหน่วงเวลาต่ำมาก ทำให้สัญญาณส่งไปยังอุปกรณ์ขับเคลื่อน (เซอร์โวมอเตอร์หรือก้านปัด) ได้ทันท่วงทีในขณะที่วัตถุกำลังเคลื่อนที่ผ่านสายพานโดยไม่หลุดตำแหน่ง
2. เพราะเหตุใดในการต่อใช้งานอุปกรณ์ขับเคลื่อน เช่น เซอร์โวมอเตอร์ หรือ โซลินอยด์ จึงห้ามใช้ไฟเลี้ยง 5V จากบอร์ดพัฒนาโดยตรง และจะต้องต่อขั้วสายแบบใดเพื่อความปลอดภัย?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: อุปกรณ์ขับเคลื่อนประเภทมอเตอร์เหนี่ยวนำจะดึงกระแสไฟฟ้าสูงมากในจังหวะเริ่มหมุน (Stall Current) และอาจเกิดแรงดันไฟฟ้าย้อนกลับ (Back EMF) ซึ่งหากดึงไฟจากบอร์ดพัฒนาโดยตรง จะทำให้ระดับแรงดันไฟฟ้าของไมโครคอนโทรลเลอร์ตก (Voltage Drop) ส่งผลให้บอร์ดเกิดการรีเซ็ตตัวเอง หรือชิปประมวลผลเสียหายได้ จึงจำเป็นต้องใช้ แหล่งจ่ายไฟแยกภายนอก (External Power Supply) และต้อง เชื่อมต่อขั้วกราวด์ร่วมกัน (Common Ground) เพื่อให้อ้างอิงระดับแรงดันของสัญญาณควบคุม PWM ได้อย่างถูกต้อง
3. ในไฟล์ app.yaml ตัวแปร EI_OBJ_DETECTION_MODEL มีหน้าที่อะไร และหากระบุพาธผิดพลาด ระบบจะมีพฤติกรรมการทำงานอย่างไร?
คลิกเพื่อดูแนวคำตอบ
แนวคำตอบ: ตัวแปร EI_OBJ_DETECTION_MODEL มีหน้าที่ชี้บอกตำแหน่งไฟล์ไบนารีโมเดล (.eim) ที่ติดตั้งอยู่บนระบบไฟล์ เพื่อให้ Video Object Detection Brick โหลดเข้าสู่หน่วยความจำตอนเริ่มระบบ หากระบุพาธผิดหรือไม่พบไฟล์ มอดูลจะไม่สามารถเริ่มกระบวนการ Inference ได้ และระบบจะส่งข้อผิดพลาด FileNotFoundError หรือ Brick Daemon จะหยุดทำงานและเข้าสู่สถานะ Failed
